## 二、待办清单（按建议顺序）

### 阶段 A：继续瘦身（本地磁盘）

#### A1. 删除 MONAI 源码子模块（省 ~177MB）★推荐
**问题**：`models/MONAI/MONAI/` 是整份 MONAI 源码。但你代码里是 `import monai` 当库用的，
说明已经 `pip install monai`，这份源码是多余的。

**做法**：
```bash
# 1) 注销并移除子模块
git submodule deinit -f models/MONAI/MONAI
git rm -f models/MONAI/MONAI

# 2) 清掉子模块在父仓库留下的缓存
rm -rf .git/modules/models/MONAI/MONAI

# 3) 删除 .gitmodules 里对应的段（若文件空了就整个删掉）
#    文件：.gitmodules
```
**注意**：这只省**本地磁盘**，不会减小别人 clone 仓库的体积（submodule 本来就只是指针）。
依赖改为在 README 里写：`pip install monai`。

#### A2. 模型权重怎么放？（41MB）
**现状**：3 个 `.pth`（DenseNet121 分类 28MB + 分割 2×6.3MB），未被 Git 追踪。

**三个选择**：
| 方案 | 优点 | 缺点 |
|---|---|---|
| ① 就留在本地 | 最简单 | clone 的人拿不到 |
| ② 传网盘/Release，README 给链接 | 干净 | 手动 |
| ③ Git LFS | 规范 | 需要配 LFS，GitHub 免费额度 1GB |

**建议**：先用 ①，等真要分享时再用 ②。

### 阶段 B：Git 历史瘦身（可选，动静较大）★谨慎

**问题**：`.git` 仍 89MB，因为历史提交里存着 MedNIST 图。别人 clone 仍是 89MB。

**做法**（需先安装 `pip install git-filter-repo`）：
```bash
# 强烈建议先备份整个文件夹！
python -m git_filter_repo --force \
  --path models/MONAI/DenseNet121/data/MedNIST \
  --path models/MONAI/DenseNet121/data/MedNIST.tar.gz \
  --invert-paths

# 或者更简单：把所有大 blob 一刀切（>5MB）
python -m git_filter_repo --force --strip-blobs-bigger-than 5M
```
**风险**：
- 会**改写所有提交的哈希**，历史记录被重写；
- 远程仓库需要 `git push --force`；
- 如果别处有 clone，那些副本会失效、需要重新 clone。

**建议**：这是个人学习仓库、没有协作者，风险可控。做完 `.git` 大概能降到几 MB。
**不想折腾的话可以跳过**，不影响日常使用。
